Asterdoc is built on JSON Schema standard [Draft 2020-12](https://json-schema.org/specification).

The schemas define the JSON shape of an artifact. To build the same artifacts in TypeScript, see the [SDK reference](/sdk).


## Installation

The schemas are available as a bundle and as individual schemas.

## Schema versions

Each version of the artifact schema is identified by a date. The current version is `__SCHEMA_VERSION__`.

Every artifact file names the version it follows in `$schema`:

```json
{
  "$schema": "https://schema.asterdoc.com/__SCHEMA_VERSION__.json",
  "kind": "form",
  "name": "residential-lease"
}
```

Artifacts serialized with the SDK (`toJSON()` and `toYAML()`) always carry the current version's address. An artifact built with the SDK is always the current version.

Every change to the artifact schema gets a new date, and a published date never changes. Each new version ships with a migration step from the version before it. An additive change has a step that only rewrites `$schema`; a breaking change has a step that converts the artifact without loss, or refuses it.

### Loading rules

Every loading surface applies the same rules: the SDK, the CLI, the AI tools, and registry consumers such as `asterdoc add`. An artifact file, read from JSON or YAML, must carry `$schema`:

| `$schema` | Result |
| --------- | ------ |
| The current version | Loads and validates as usual. |
| An earlier version | Upgrades in memory through the migration steps, then loads and validates as the current version. The file is not changed. |
| A version newer than the SDK knows | Fails with a newer-version error: "newer than this SDK knows; update @asterdoc/core". |
| Missing | Fails with a missing-version error. |
| An unpublished earlier date, the undated `schema.json`, or a non-Asterdoc address | Fails with an unknown-version error. |

An earlier version that a migration step cannot convert without loss fails with a not-upgradable error. Pass `strictSchema: true` to accept only the current version: an earlier one then fails with an outdated-version error. The registry publishes an artifact on an earlier version rewritten at the current one, so every new release is on the current version, while releases published earlier keep their own version. A bundle's inline parts each upgrade from the version they declare, earlier or later than the bundle's.

A later SDK can load, validate and extract an artifact written for an earlier version. Renders are not promised to be byte-identical across releases; the durable record of a filing is its sealed canonical PDF and hash.

In the SDK, `load()` and `safeLoad()` read file content and apply these rules; an error is a `SchemaVersionError` with a `code` of `missing-version`, `newer-version`, `unknown-version`, `not-upgradable`, `no-migration-path`, or, with `strictSchema`, `outdated-version`. Every other way to create an artifact takes an object that may have been built in memory, so it accepts one without `$schema`, and applies the same rules to a `$schema` it does carry: `loadFromObject()`, `a.form()`, `a.document()`, `a.checklist()` and `a.bundle()` with an object, their `.from()` and `.safeFrom()`, and the builder's `.from()`. Each takes `strictSchema` in its options, a bundle's included. An instance loaded from an earlier version names it in `migratedFrom`, and so does each runtime filled or prepared from it: a runtime's `toJSON()` writes the definition as stored, so a restore upgrades it again. `validate()` validates the upgraded artifact, and reports a version error as an issue at `$schema`. A bundle applies the rules to each inline part too, and the error names the part. To rewrite a file at the current version, use [`migrate`](/cli/commands/migrate).

```ts
import { load, SchemaVersionError } from '@asterdoc/sdk'

try {
  const artifact = load(fileContents)
  if (artifact.migratedFrom) console.log(`upgraded from ${artifact.migratedFrom}`)
} catch (error) {
  if (error instanceof SchemaVersionError) console.error(error.code, error.message)
}
```

### Version history

| Version | Changes |
| ------- | ------- |
| `2026-10-28` | First Asterdoc version. It has the same shape as Paradoc's `2026-10-02` at `schema.paradoc.dev`. To move a Paradoc artifact to it, bring the artifact to `2026-10-02` with Paradoc 0.8 if it is older, then run `asterdoc migrate <file> --from 2026-10-28`. Only `$schema` changes. |
| `2026-11-06` | Adds the optional `format.date` setting to PDF layers. Only `$schema` changes. |
| `2026-11-10` | Adds the optional value-formatting settings on layers, bindings and fields. Only `$schema` changes. |

## Hosted server

The hosted service exposes the current prerelease schema set and the live root schemas.

| Schema           | URL                                                 |
| ---------------- | --------------------------------------------------- |
| Versioned bundle | `https://schema.asterdoc.com/__SCHEMA_VERSION__.json`      |
| Individual items | `https://schema.asterdoc.com/__SCHEMA_VERSION__/form.json`, `bundle.json`, `checklist.json`, `document.json` |
| Latest bundle    | `https://schema.asterdoc.com/schema.json`, for editors. It names no version, so an artifact file uses a dated address. |

**Usage**

```typescript
import bundledSchema from '@asterdoc/schemas/schema.json'
import { SCHEMA_VERSION, ASTERDOC_SCHEMA_URL, readSchemaAddress } from '@asterdoc/schemas'

SCHEMA_VERSION // '__SCHEMA_VERSION__'
ASTERDOC_SCHEMA_URL // 'https://schema.asterdoc.com/__SCHEMA_VERSION__.json'
readSchemaAddress('https://schema.asterdoc.com/__SCHEMA_VERSION__.json') // { kind: 'known', version: '__SCHEMA_VERSION__' }
```

## Schema Reference

The Asterdoc schemas are broken down into 2 categories:


| Category                           | Description                                                                                                                         |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| [Artifacts](/schemas/artifacts)    | Top-level artifact types that define document structures.                                                                           |
| [Primitives](/schemas/primitives)  | Low-level types for representing common data types like addresses, monetary amounts, and more. |

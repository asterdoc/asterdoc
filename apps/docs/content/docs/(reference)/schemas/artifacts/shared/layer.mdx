A Layer defines how an artifact can be rendered into a specific format. Layers enable artifacts to have multiple output representations (PDF, HTML, Markdown, etc.).

```typescript
type Layer = InlineLayer | FileLayer
```

## MIME types

The layer's `mimeType` selects its renderer.

| MIME type | Layer kind | Rendered by |
| --------- | ---------- | ----------- |
| `text/markdown`, `text/html`, `text/plain` | inline or file | Built-in text renderer |
| `application/pdf` | file | Built-in PDF renderer, using `bindings` |
| `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | file | Built-in DOCX renderer |
| `text/tsx`, `text/jsx` | file only, forms only | A renderer you register, such as `reactLayerRenderers()` from `@asterdoc/react-pdf` |

Any other MIME type needs a renderer passed in the `renderers` option of `render()`, keyed by MIME type.

A `text/tsx` or `text/jsx` layer names a React composition module by `path`, so it must be a file layer. An inline layer with either MIME type fails validation. The check ignores case, so `TEXT/TSX` is rejected too. Only a form can declare a React layer: a composition renders a form and its data, so a document or checklist with one fails validation.

## Bindings

Only a PDF file layer takes `bindings` and `bindingsFrom`. Each key of `bindings` is a fully qualified AcroForm field name, as `asterdoc inspect` prints it, and each value is the Asterdoc path that fills it, such as `fields.name` or `parties.buyer.name`. A text, Markdown, HTML or DOCX template names each value directly as `{{fields.fieldName}}`. Validation rejects `bindings` or `bindingsFrom` on any other layer.

```json
{
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "w-9.pdf",
  "bindings": {
    "topmostSubform[0].Page1[0].f1_01[0]": "parties.taxpayer.name",
    "topmostSubform[0].Page1[0].f1_02[0]": "fields.businessName"
  }
}
```

A binding value can also be an object: `path` is the string the binding would be, and `format` sets how that one value prints, merged over the layer's `format`. A joined path applies the format to each value before the join. An option test such as `fields.status:married` fills a checkbox and prints nothing, and a split part such as `fields.ssn:2` prints a piece of the raw value, so validation rejects a `format` on either.

```json
"bindings": {
  "topmostSubform[0].Page1[0].f1_03[0]": { "path": "fields.signedOn", "format": { "date": { "pattern": "YYYY-MM-DD" } } }
}
```

A layer that reuses bindings through `bindingsFrom` takes each binding with its own `format`. Its layer `format` stays its own.

## Format

`format` sets how a layer prints values. Any layer that prints values can declare one: PDF, text (`text/plain`, `text/markdown`, `text/html`), DOCX, and React (`text/tsx`, `text/jsx`), file or inline. The MIME check ignores case. Any other layer fails validation.

Levels apply from lowest to highest: the caller's formatter, then the layer's `format`, then a binding's `format`. Each kind merges per property, so a binding's `money` keeps the layer's other money choices, and a higher `locale` replaces a lower one. React layers accept a `format` but do not apply it yet. See [Artifact formatting](/sdk/renderers/pdf#artifact-formatting).

## SignatureSlot

A signature slot declares one signing field on a layer. Each slot binds a party
to a placement; the seal pipeline resolves every slot to concrete PDF
coordinates.

<PropertiesTable properties={[
  {
    name: 'party',

    description: 'Party this slot binds to. index is 0-based for multi-party roles and defaults to 0',
  },
  {
    name: 'type',
    type: "'signature' | 'initials' | 'date_signed' | 'capacity' | 'printed_name'",
    description: 'Type of signing field',
  },
  {
    name: 'placement',
    type: "SignatureSlotPlacement",
    description: "Where the field lands: 'flow' (in the content flow; located after conversion), a text anchor, or absolute coordinates",
  },
  {
    name: 'required',
    type: 'boolean',
    description: 'Whether this slot must be signed. Defaults to true',
    isOptional: true,
  },
  {
    name: 'label',
    type: 'string',
    description: 'Human-readable label',
    isOptional: true,
  },
]} />

```typescript
type SignatureSlotPlacement =
  | 'flow'
  | { page: number; x: number; y: number; width: number; height: number }
  | {
      anchor: { text: string; offsetX?: number; offsetY?: number; occurrence?: number }
      width: number
      height: number
    }
```

`signatures` is the only place a layer declares signing fields.

## Examples

```yaml tab="YAML"
layers:
  # Inline layer with markdown content
  markdown:
    kind: inline
    mimeType: text/markdown
    title: Markdown Version
    text: |
      # Welcome

      This is the content of the document with {{ fields.name }} placeholder.

  # File layer referencing external PDF
  pdf:
    kind: file
    mimeType: application/pdf
    path: /templates/contract.pdf
    title: PDF Version
    bindings:
      client_name: clientName
      contract_date: contractDate

  # File layer pointing at a React composition module
  composition:
    kind: file
    mimeType: text/tsx
    path: ./contract.tsx
    title: React Version
```

```json tab="JSON"
{
  "layers": {
    "markdown": {
      "kind": "inline",
      "mimeType": "text/markdown",
      "title": "Markdown Version",
      "text": "# Welcome\n\nThis is the content of the document with {{ fields.name }} placeholder."
    },
    "pdf": {
      "kind": "file",
      "mimeType": "application/pdf",
      "path": "/templates/contract.pdf",
      "title": "PDF Version",
      "bindings": {
        "client_name": "clientName",
        "contract_date": "contractDate"
      }
    },
    "composition": {
      "kind": "file",
      "mimeType": "text/tsx",
      "path": "./contract.tsx",
      "title": "React Version"
    }
  }
}
```

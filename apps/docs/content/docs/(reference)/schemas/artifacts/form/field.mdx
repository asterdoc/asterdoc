---
title: FormField
description: Field definitions for capturing user input
---

FormField is a union type representing all possible field types in a form. Each field type has a `type` discriminator and shares common base properties.

```typescript
type FormField =
  | TextField
  | BooleanField
  | NumberField
  | CoordinateField
  | BboxField
  | MoneyField
  | AddressField
  | CountryField
  | RegionField
  | PhoneField
  | DurationField
  | EmailField
  | UuidField
  | UriField
  | EnumField
  | DateField
  | DatetimeField
  | TimeField
  | PersonField
  | OrganizationField
  | IdentificationField
  | MultiselectField
  | PercentageField
  | RatingField
  | FieldsetField
  | ListField
```

## Field Types

Each field type includes all [BaseField](#basefield) properties plus the type-specific properties listed below. A field with any other key fails validation, and the error names the key.

## Examples

```yaml tab="YAML"
fields:
  # Text field with validation
  firstName:
    type: text
    label: First Name
    required: true
    minLength: 1
    maxLength: 100

  # Email field
  email:
    type: email
    label: Email Address
    required: true

  # Enum dropdown
  preferredContact:
    type: enum
    label: Preferred Contact Method
    enum: [{ value: "email" }, { value: "phone" }, { value: "mail" }]
    default: email

  # Money field
  annualIncome:
    type: money
    label: Annual Income
    required: true
    min: 0

  # Date with constraints
  birthDate:
    type: date
    label: Date of Birth
    max: "2006-01-01"

  # Conditional field
  maritalStatus:
    type: enum
    enum:
      - value: single
        label: Single
      - value: married
        label: Married
  spouseName:
    type: person
    label: Spouse Information
    visible: "fields.maritalStatus == 'married'"
    required: "fields.maritalStatus == 'married'"

  # Nested fieldset
  emergencyContact:
    type: fieldset
    label: Emergency Contact
    fields:
      name:
        type: text
        label: Contact Name
        required: true
      phone:
        type: phone
        label: Contact Phone
        required: true
```

## Visibility cascade

`visible` and `required` compose into one effective status (`hidden < optional < required`), and that status cascades through fieldsets:

- A hidden fieldset hides its whole subtree. Children of a hidden container are hidden regardless of their own `visible`.
- `required` follows effective visibility: a field is only required if it is also visible. A hidden field is never required.
- A parent's `required` does not force its children. An optional fieldset can still hold required children, and a required fieldset does not make its children required.

So you author two conditions (`visible`, `required`), and the engine resolves them into a single status per field, with hidden winning over everything below it.

Renders an artifact layer to a file or stdout.

## Usage

```bash
asterdoc render <artifact> [options]
```

## Arguments

| Argument | Description |
|----------|-------------|
| `artifact` | Artifact file (JSON/YAML) or `-` for stdin |

## Options

| Option | Description |
|--------|-------------|
| `--data <pathOrJson>` | Complete, valid data payload: file path (JSON/YAML), `-` for stdin, or inline JSON |
| `--out <file>` | Write output to file (defaults to stdout) |
| `--format <style>` | Summary format: `pretty` or `json` (default: pretty) |
| `--layer <key>` | Layer key to use (defaults to `defaultLayer`, else the first declared layer) |
| `--dry-run` | Validate and resolve layer without rendering |
| `--draft` | Render form data that is not complete: a required field with no value prints empty, and the command lists each one |
| `--check` | After a PDF render with `--data` and `--out`: read the PDF back and compare each value with the data |

## Description

The `render` command reads an artifact and resolves the requested layer. With
`--data`, it selects the text, PDF, or DOCX implementation automatically from
the layer's MIME type and fills the output. Without data, it returns the raw
layer content. File-backed layers resolve relative to the artifact file.
For artifacts read from stdin, file-backed layers resolve from the current
working directory.

## Examples

Render default layer to stdout:

```bash
asterdoc render my-form.yaml
```

Render specific layer:

```bash
asterdoc render my-form.yaml --layer markdown
```

Fill a PDF layer without choosing a renderer:

```bash
asterdoc render my-form.yaml --layer pdf --data answers.json --out completed.pdf
```

Render to file:

```bash
asterdoc render my-form.yaml --out output.md
```

Dry run (validate only):

```bash
asterdoc render my-form.yaml --dry-run
```

## Output

When rendering to file:

```
✓ Layer rendered to output.md
  Artifact: lease-agreement
  Layer: markdown
  Type: text/markdown
```

Dry run output:

```
Dry run summary:
  Artifact:   lease-agreement (form)
  Version:    1.0.0
  Layer:      markdown
  Layer kind: inline
  MIME type:  text/markdown
  Source:     lease-agreement.yaml
```

An artifact argument may be a file path or an installed `@namespace/name` reference from `.asterdoc/lock.json`. An uninstalled reference fails with an error.

`--data` applies only to forms. Other artifact kinds ignore it with a warning. A PDF layer fills from the bindings the artifact declares. Invalid form data stops rendering. So does data that is not complete: a required field with no value, or a rule that is not met.
Add `--draft` to render data that is not complete. The command still refuses a value the form does not accept, and it lists on stderr each required field with no value and each rule that is not met. With `--format json` and `--out`, the list is in `draft.open`.

Valid data that a PDF layer cannot draw stops rendering before anything is drawn: a value too wide for its field, longer than a comb, or with a character the field's font cannot draw. The command lists each one on stderr with its path; with `--format json` it prints `{ success: false, layer, renderProblems }`. It is the report of `asterdoc data validate --render-check <layer>`.

Add `--check` to a PDF render with `--data` and `--out` to read the file back through the layer's bindings. The command prints one `Read back` line with the number of values that equal the data, and lists each value that differs, each value whose box is empty and each box that cannot be read as a value; with any of those it exits 1, and the file stays written. A value that prints in a form that does not read back as one value, such as a telephone number printed with no country code, is listed under `Not compared` with the text its box holds, and is not a fault. A value the form computes is not in the data, so it is not compared. With `--format json`, the result is in `check`. React layers also require an SDK React renderer; the CLI reports the core `UnregisteredLayerRendererError` for them.

Initializes a new Asterdoc project in the current or specified directory.

## Usage

```bash
asterdoc init [directory] [options]
```

## Arguments

| Argument | Description |
|----------|-------------|
| `directory` | Directory to initialize (defaults to current directory) |

## Options

| Option | Description |
|--------|-------------|
| `-y, --yes` | Non-interactive mode (skip prompts) |
| `--name <name>` | Project title (required in non-interactive mode) |
| `--description <desc>` | Project description |
| `--visibility <public\|private>` | Project visibility (default: private) |
| `--nested` | Allow creating nested project inside existing project |
| `--dry-run` | Preview without creating files |

## Description

The `init` command creates a new Asterdoc project with the following structure:

```
my-project/
├── asterdoc.json      # Project manifest
└── .asterdoc/         # CLI state directory (empty until an artifact is installed)
```

The manifest holds `$schema`, `name`, `title`, `description`, and `visibility`. The name is `@your-org/<title-slug>`; replace `your-org` with your own namespace. Add registries and other settings by hand (see [Projects](/cli/projects#the-project-manifest)).

In interactive mode, you'll be prompted for:
- Project title
- Description (optional)
- Visibility (public or private)
- Directory name

## Examples

Interactive initialization:

```bash
asterdoc init
```

Non-interactive with all options:

```bash
asterdoc init --yes --name "My Project" --visibility private
```

Initialize in a specific directory:

```bash
asterdoc init my-new-project
```

Preview what would be created:

```bash
asterdoc init --dry-run --yes --name "Test Project"
```

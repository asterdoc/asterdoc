---
title: pdfRenderer
description: Fill PDF forms with AcroForm field support
---

Fill PDF forms with Asterdoc's dependency-light PDF implementation. It supports
AcroForm text fields, checkboxes, dropdowns, and radio buttons with automatic
field formatting, plus coordinate-based text and image overlays.

## Example

```ts
import { a } from '@asterdoc/core'
import { pdfRenderer } from '@asterdoc/render/pdf'
import { createFsResolver } from '@asterdoc/resolvers/fs'
import { writeFileSync } from 'node:fs'

const resolver = createFsResolver({ root: process.cwd() })

const form = await a.form.load({
  name: 'w9',
  fields: {
    name: { type: 'text', label: 'Name' },
    businessName: { type: 'text', label: 'Business Name' },
    taxClassification: { type: 'enum', enum: [{ value: 'individual' }, { value: 'llc' }, { value: 'corporation' }] },
    address: { type: 'text', label: 'Address' },
    ssn: { type: 'text', label: 'SSN' }
  },
  layers: {
    pdf: {
      kind: 'file',
      mimeType: 'application/pdf',
      path: '/templates/w9-form.pdf',
      bindings: {
        // Map PDF field names to form field expressions
        'topmostSubform[0].Page1[0].f1_1[0]': 'name',
        'topmostSubform[0].Page1[0].f1_2[0]': 'businessName',
        'topmostSubform[0].Page1[0].c1_1[0]': 'taxClassification:individual',
        'topmostSubform[0].Page1[0].c1_1[1]': 'taxClassification:llc',
        'topmostSubform[0].Page1[0].f1_5[0]': 'address'
      }
    }
  },
  defaultLayer: 'pdf'
}, { resolver })

// Fill the form with data
const filled = form.fill({
  fields: {
    name: 'John Smith',
    businessName: 'Smith Consulting',
    taxClassification: 'llc',
    address: '123 Main St, New York, NY 10001'
  }
})

// The resolver was bound when the form was constructed, so every instance
// derived from it — filled included — carries it. render() doesn't take one.
const output = await filled.render({
  renderer: pdfRenderer()
})

// output is Uint8Array - write to file
writeFileSync('w9-filled.pdf', output)
```

A `PdfOverlay` is either text or an image placed at `page` (one-based), `x`,
and `y` (PDF points from the bottom-left corner). A text overlay carries `text`
or a `field` path to read from the data (with or without the `fields.` prefix), plus optional `fontSize`, `width`,
`height`, `color`, and `font`. Overlay text follows the same font order and failure
rules as field values, after the overlay's own `font` when it names one, so one
render can draw a heading in a bold font and body text in a regular one. A text overlay with a `width` fails with an
`overflow` error when its text does not fit at 6 points. An image overlay
carries `image` bytes, `mediaType` (`'image/png'` or `'image/jpeg'`), `width`,
`height`, and optional `fit`.

Returns a `Promise<Uint8Array>` containing the filled PDF document.

## Inspecting PDF Fields

Use `inspectAcroFormFields()` to discover field names in a PDF template:

```ts
import { inspectAcroFormFields } from '@asterdoc/render/pdf'
import fs from 'fs'

const template = fs.readFileSync('form.pdf')
const fields = await inspectAcroFormFields(template)

console.log(fields)
// [
//   { name: 'f1_1', type: 'text', required: true },
//   { name: 'c1_1', type: 'checkbox', value: false },
//   { name: 'dropdown1', type: 'dropdown', value: ['Option A'] }
// ]
```

## PDF utilities

`@asterdoc/render/pdf` exports dependency-light helpers for working with PDF
bytes directly.

| Function | Description |
|----------|-------------|
| `inspectPdf(pdf)` | Returns `{ pageCount, pages }`, with each page's one-based number, `width`, and `height` in PDF points |
| `flattenPdf(pdf)` | Burns AcroForm field appearances into the pages and removes the interactive controls. A widget a viewer does not show (Hidden or NoView) is removed without being drawn. A PDF with no AcroForm returns unchanged |
| `selectPdfPages(pdf, pages)` | Returns a new PDF with only the given one-based pages, in source order. Dropped pages, and form fields that sit only on them, are not in the file. Pages must be unique positive integers that exist |
| `mergePdfs(pdfs)` | Concatenates PDFs into one, keeping every page in order. A single source returns unchanged |

```ts
import { flattenPdf, inspectPdf, mergePdfs, selectPdfPages } from '@asterdoc/render/pdf'

const { pageCount } = await inspectPdf(filled)
const flat = await flattenPdf(filled)
const firstTwo = await selectPdfPages(flat, [1, 2])
const packet = await mergePdfs([firstTwo, coverLetter])
```

`mergePdfs` throws `PdfMergeError` when a source has no catalog or pages, or
cannot be read. Its `source` property is the zero-based index of that source.

Every function that reads or writes a PDF, from `renderPdf` to `mergePdfs`,
refuses an encrypted PDF with `PdfEncryptedError`, whose `code` is
`encrypted_pdf`. An encrypted file stores its strings and streams enciphered,
so a filled or copied value would be unreadable. Remove the encryption first.

### Digital signature fields

Three helpers write and read the file structure a digital signature lives in.
They do not sign: you produce the signature container (for example a CMS
`SignedData`) with your own keys.

| Function | Description |
|----------|-------------|
| `preparePdfSignature(pdf, options)` | Appends an incremental update with an invisible signature field on the first page, an AcroForm with `/SigFlags 3`, and a signature dictionary whose `/Contents` reserves `contentsSize` bytes. Returns `{ bytes, byteRange }` with the byte range already written. `name`, `reason`, `location` and `contactInfo` may use any script |
| `signedBytes(prepared)` | The bytes the byte range covers: what your container signs |
| `embedPdfSignature(prepared, container)` | Writes the container into `/Contents`. Throws when it is larger than the reserved size |
| `readPdfSignature(pdf)` | Reads the newest signature dictionary: its container, byte range, signed bytes, text entries and signing time. `coversWholeFile` is false when any byte outside the container is unsigned, such as an update appended after signing |

```ts
import { embedPdfSignature, preparePdfSignature, signedBytes } from '@asterdoc/render/pdf'

const prepared = await preparePdfSignature(pdf, { contentsSize: 16384, signingTime: new Date(), name: 'Ada Lovelace' })
const signed = embedPdfSignature(prepared, createCmsSignature(signedBytes(prepared)))
```

The same entry point exports the signature placement helpers the SDK
re-exports: `locate`, `locator`, `LocateError`, `extractFieldsFromPdf`,
`UnknownMarkerError`, and the marker `encode` and `decodeAll` functions.
`extractFieldsFromPdf` and `locate` throw `UnknownMarkerError`, naming the page,
signer, and field type code, when a marker's field type is not signature or
initials.

## Binding Syntax

PDF bindings map AcroForm field names to Asterdoc paths, with special syntax for complex cases. A path may carry the `fields.` prefix (`fields.taxType` is `taxType`), and space around `:` is ignored. Filling, extraction, the fit check, and validation all parse a binding value this way, and all read a split part only from a whole number from 1.

Every binding key must name a form field of the template. `renderPdf` fails with `PdfBindingKeyError`, naming each key the template does not have, instead of filling the rest. A binding value may name only paths the fill data carries: fields, `parties`, `defs`, `annexes`, and the signing roots `_signers` and `_captures`.

### Simple Binding

```ts
bindings: {
  'pdfFieldName': 'formFieldName'
}
```

### Enum Checkboxes

For PDF checkboxes that represent enum values, use `:value` syntax:

```ts
bindings: {
  'checkbox_individual': 'taxType:individual',  // Check if taxType === 'individual'
  'checkbox_llc': 'taxType:llc',                // Check if taxType === 'llc'
  'checkbox_corp': 'taxType:corporation'        // Check if taxType === 'corporation'
}
```

### Split Fields

For fields split across multiple PDF inputs (like SSN), use `:partNumber` syntax:

```ts
bindings: {
  'ssn_part1': 'ssn:1',  // First part: "123" from "123-45-6789"
  'ssn_part2': 'ssn:2',  // Second part: "45"
  'ssn_part3': 'ssn:3'   // Third part: "6789"
}
```

### Several Values in One Field

Print several values in one PDF field with a template, a binding object with `template` in place of `path`. It uses the template language of text layers: `{{ }}` placeholders with any expression and format modifiers, `{{#if}}`, `{{#unless}}`, `{{else}}` and `{{! comment }}`.

```ts
bindings: {
  'cityStateZip': { template: '{{fields.city}}, {{fields.state}} {{fields.zipCode}}' }  // "San Francisco, CA 94105"
}
```

A binding object holds `path` or `template`, never both, and a template takes no `part`; a placeholder does: `{{fields.dob | part="year"}}`. A template is 1 to 2000 characters. It refuses `{{#each}}`, because a field prints a fixed text and each list row binds to its own field, and signing directives, because a PDF layer places signing marks through its signature slots.

Each placeholder prints as a path binding to the same path does: a choice prints its option value, masks apply, then the layer `format`, the binding `format`, and the placeholder's own modifiers. The binding's `format.case` changes the whole field, the template's own text included. When every placeholder the template reached prints nothing, the field stays empty. A line break in the template starts a new line in a multi-line field; `validateLayers()` reports an error for a single-line field. See [PDF layers](/guides/pdf-layers#several-values-in-one-field).

A comma-joined string such as `'city,state,zipCode'` is not a binding. It fails with `PdfBindingSyntaxError`: ``Binding "city, state" joins several paths with a comma, which a binding does not do; print several values in one field with a template, such as {"template":"{{fields.city}}, {{fields.state}}"}.`` A qualifier on a path (`'ssn:1'`) is still one path. An empty path or qualifier fails too.

### Nested Paths

Access nested data using dot notation:

```ts
bindings: {
  'buyer_name': 'parties.buyer.name'
}
```

### Reading bindings back

[Extraction](/sdk/artifacts/form#extracting-data-from-a-filled-pdf) reverses simple, nested, enum checkbox, and split bindings exactly. A template field is read back when its text splits into the template's values in exactly one way: `Boston, MA 02110` with `{{fields.city}}, {{fields.state}} {{fields.zip}}` is recovered. Text that splits more than one way, a template that prints a computed value, and a filled box of any kind bound to a computed value are reported as not recoverable, and text that does not match the template is unparseable. A value printed through a format is read back through it; a format that drops detail, such as `case: upper` or `money.fractionDigits: 0`, marks the recovered value `lossy`. See [Reading a filled PDF back](/guides/value-formatting#reading-a-filled-pdf-back).

## Automatic Serialization

Field values are automatically serialized based on their schema types:

```ts
// Money fields formatted as "$50,000.00"
// Date fields formatted as "Apr 1, 2024"
// Phone fields formatted as "+12025550143"
```

A layer or binding `format` changes this per output, such as `phone: { style: 'national' }` for `(202) 555-0143`. See [Formatting values](/guides/value-formatting).

## Field appearance

Filling draws each value the way the form's designer set up the field:

- **Size:** the font size in the field's default appearance, or automatic sizing when that size is zero.
- **Alignment:** left, centered, or right, from the field's quadding.
- **Color:** the color in the field's default appearance.
- **Comb:** one character per box across the field's `MaxLen` boxes, so a TIN lands one digit per box.
- **Multiline:** text wraps within the field and keeps explicit line breaks.
- **Choice:** a combo box shows the selected option's display text; a list box shows every selected value, one per line.

A value that does not fit is reduced in size, down to `MIN_FONT_SIZE` (6 points). Below that, filling fails instead of clipping the value. Checkbox and radio fields are unchanged.

## Checking bindings before filling

`validate()` fails a binding whose value is not a known Asterdoc path, and `validateLayers()` fails a binding whose key is not an AcroForm field in the template. Both errors name the layer and the key. `form.load` refuses such a key too, with the `PdfBindingKeyError` a render throws. `validateLayers()` also fails a binding to a text or choice field with more than one widget, naming the field and its pages, since a value would print in each widget. `inspectAcroFormFields` lists every widget of a field in `widgets`.

`validateLayers()`, `asterdoc validate`, and the `validate_artifact` AI tool also check each binding of a form's PDF layer to a text field before any data exists. The check builds values the bound field accepts and lays them out with the same code filling uses, in the fonts filling would choose: the layer's declared TrueType font, then the standard font of the binding or the layer (Helvetica unless the artifact chooses Courier). The font a PDF field itself names is not used. A value that passes this check can still be too wide for its box, or need a character no font has. `validate()` reads no layer: the render check, `draft.renderProblems(layer)`, checks each actual value, and `render()`, `prepareSeal()` and `seal()` run it first and throw `RenderRefusedError` with its report.

A text, email, uuid, or uri field is checked at its length bound: `maxLength` characters, or the length its `pattern` bounds, whichever is shorter. A uuid field without a pattern takes its 36-character canonical form. Two values of that length are laid out:

- **A typical value** is made of the repeated reference text `The quick brown fox jumps over the lazy dog ` (exported as `TYPICAL_TEXT`). It holds every lowercase letter, one capital, and word spaces at about the rate English prose has them. Its mean advance in Helvetica, 456 units per 1000, sits just above that of letter-frequency-weighted English text (441), so a box that holds it holds ordinary answers. A position the pattern constrains holds the allowed character nearest the allowed characters' mean width. If the typical value cannot fit at 6 points, it is an **error**.
- **The widest value** holds the widest character each position allows: for an open position, the widest Latin letter or digit in the font (`W` in Helvetica). If only this value cannot fit, it is a **warning**: ordinary answers fill, and an answer made mostly of wide capitals does not.

Other bindings are checked exactly, and a failure is an **error**:

- **Comb fields:** a value longer than the field's boxes (`comb-length`).
- **Split bindings** (`ssn:3`): the matching hyphen-separated part of the pattern. When the pattern does not fix where the hyphens fall, the part is bounded by the whole value's `maxLength`.
- **Enum fields:** the widest option value, since a PDF text box writes the value. **Multiselect fields:** the widest `max` option values, or all of them, joined with `, `.
- **Template bindings:** each text the template can print, one for each combination of its `{{#if}}` blocks, with the template's own text around the values the bound fields accept. A template with a computed placeholder is not measured.

The check measures what the binding prints, after the layer's and the binding's `format` and `case`. Under `choice.display: label` it measures the labels, and under `boolean` labels both labels. Country and region names are measured at every name the format can print. A masked text field is measured at the widest character each mask position allows, with its literals unless `text.mask` is `false`. A phone under `phone.style` is measured at the longest number the style prints, in `phone.region`'s plan or any plan, and a `part` at the most digits it holds. Upper case is applied before measuring, since it can lengthen a value.

A bound text field with nothing bounding its length is a **warning** (`unbounded`). `validateLayers()` returns warnings in `result.warnings`; they do not fail validation. Composite parts such as `address.line1`, party values, and computed values are not checked.

The check is also exported on its own:

```ts
import { checkPdfBindingFit } from '@asterdoc/render/pdf'

const issues = await checkPdfBindingFit({ template: pdfBytes, form, bindings })
// [{ field: 'amountSource', binding: 'fields.amountSource', paths: ['fields.amountSource'], severity: 'error', reason: 'overflow', value: 'typical', limit: 6, length: 200, message: '...' }]
```

## Fonts

Filled values draw in the standard PDF fonts every viewer has, so nothing is embedded: Helvetica, or Courier (monospace), each with the Windows Latin 1 (WinAnsi) characters. The font the PDF field itself names is not used. A field draws in:

1. the font its binding chooses: `{ "path": "fields.ssn", "font": "Courier" }`;
2. else the font its PDF layer chooses: `"font": "Courier"`;
3. else Helvetica.

An artifact may choose `"Helvetica"` or `"Courier"`. The choice is in the artifact, not in the data, because whether a value fits depends on it, and the render check measures with it:

```json
"pdf": {
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "w-9.pdf",
  "font": "Courier",
  "bindings": { "f1_01": { "path": "fields.name", "font": "Helvetica" } }
}
```

A standard font cannot draw a character outside Windows Latin 1, such as Chinese, Arabic, Cyrillic, Greek, Polish ł, Czech č, Turkish ğ or Vietnamese ễ. The render check reports such a value, and a render refuses it with the same report.

### A layer font

A layer can declare its own TrueType font (`.ttf`) instead, as a design choice. It is read through the same resolver as the layer's PDF, so it travels with the artifact. Each character draws in it when it has the glyph, else in the field's standard font, so one value can mix the two. It is embedded as a subset of the glyphs drawn, so a large font adds kilobytes to the output. Only TrueType-outline fonts are supported; an OpenType font with CFF outlines, a font collection, or a WOFF file is refused.

```json
"pdf": {
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "w-9.pdf",
  "font": { "path": "fonts/Corporate-Regular.ttf" }
}
```

There is no render-time font: the fonts belong to the artifact, so the render check and the render measure the same text with the same fonts.

To lay out overlay text yourself, measure it first. `pdfFontMetrics(font)` reads a `PdfFont` and returns `canDraw(text)`, true when every character has a glyph and none needs shaping, and `width(text, size)`, the width in points that an overlay draws:

```ts
import { pdfFontMetrics } from '@asterdoc/render/pdf'

const metrics = pdfFontMetrics(font)
if (metrics.canDraw(name) && metrics.width(name, 10) <= 495) {
  // draw `name` as one overlay line
}
```

Filling draws one glyph per character, left to right. It does not shape text, so Arabic, Hebrew, Devanagari, Thai, and other scripts that need shaping or right-to-left ordering are refused, whatever font is available. The render check reports such a value first. Render documents in those scripts from a [React composition layer](/guides/react-layers).

## Errors

A value that cannot be drawn faithfully fails with `PdfFieldFillError`. It names the field (or the text overlay), the artifact paths the field prints, and the reason. `field` is the PDF field name. `paths` holds the paths as fill data writes them, such as `['fields.nameInNativeAlphabet']` or `['parties.client.lastName']`; a template binding gives each path of its template. An overlay with fixed text has no `paths`.

```text
Cannot fill PDF field "form1[0].Page1[0].NativeName[0]" with fields.nameInNativeAlphabet: no available font can draw "Հ" (U+0540). The field draws in Helvetica, a standard PDF font with the Windows Latin 1 characters only. To print this character, declare a TrueType font that has it on the PDF layer of the artifact: "font": { "path": "<file>.ttf" }.
```

| `reason` | When | Detail |
|---|---|---|
| `overflow` | The value does not fit at the minimum size | `limit`: the minimum size in points |
| `comb-length` | The value has more characters than the comb field has boxes | `limit`: the number of boxes |
| `missing-glyph` | No available font can draw a character | `character`: the character. Declare a TrueType font on the PDF layer that has it. |
| `unsupported-script` | The value is in a script that needs shaping | `script`: the script, such as `Arabic`; `character`: its first character in the value. No font corrects this. |

### Checking values before a render

`validate()` answers whether the data matches the artifact; it reads no layer. Whether valid data renders on a PDF layer is the layer's render check: `draft.renderProblems(layer)` reports every value the layer would refuse, with the code rendering draws with, before any render. A render runs the same check first and refuses with the same report, `RenderRefusedError`, before it draws anything: see [Rendering a layer](/sdk/artifacts/form#rendering-a-layer). `validateLayers()`, `asterdoc validate`, and the `validate_artifact` AI tool run the render check on the values of each test in a form's `tests` whose data is valid, and report each problem as an error that names the layer, the test, the PDF field and the path.

`readPdfPrintProfile()` and `pdfPrintFailures()` are the functions behind that check: the first reads a PDF layer once, the second checks data against it and reads no file.

```ts
import { pdfPrintFailures, readPdfPrintProfile } from '@asterdoc/render/pdf'

const profile = await readPdfPrintProfile({ template, form, bindings })
for (const failure of pdfPrintFailures(profile, { data })) console.error(failure.field, failure.paths, failure.message)
```

A supplied or declared font that cannot be used fails with `PdfFontError`, naming its `source` and the `problem`: `unreadable`, `unsupported-format`, or `not-embeddable` (its license forbids embedding). A declared font the resolver cannot find fails the same way a missing layer file does.

```ts
import { PdfFieldFillError, PdfFontError, renderPdf } from '@asterdoc/render/pdf'

try {
  await renderPdf({ template, data, bindings })
} catch (error) {
  if (error instanceof PdfFieldFillError) console.error(error.field, error.reason)
  else if (error instanceof PdfFontError) console.error(error.source, error.problem)
  else throw error
}
```

## Artifact formatting

Pass `formatter` to the artifact's `render()`, `prepareSeal()`, or `seal()` call to use the same presentation on every pass. Direct `renderPdf()` and `pdfRenderer()` also accept a formatter. Artifact context overrides the renderer default.

When the template pre-prints the currency symbol beside each money box, as IRS 1099 forms do, the layer declares it:

```json
"pdfCopyA": {
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "1099-nec-A.pdf",
  "format": { "money": { "currencyDisplay": "none" } }
}
```

Every render of that layer then prints `12,000.00` instead of `$12,000.00`, with no formatter to configure. The layer's format applies over the formatter the render uses, so its locale and digits still apply; only the symbol goes. The amount keeps its currency's fraction digits. Other layers of the artifact, such as its Markdown, keep the symbol, and a layer that reuses these bindings through `bindingsFrom` declares its own `format`.

`money` also takes `fractionDigits` (`0` or `2`) and `useGrouping`; see [Format](/schemas/artifacts/shared/layer#format). Declare the money field's `currency` too: [extraction](/sdk/artifacts/form#extracting-data-from-a-filled-pdf) reads an amount printed without a symbol in that currency. Text and DOCX layers take the same `format`; see [Format](/schemas/artifacts/shared/layer#format).

When the template asks for dates in one numeric order, such as mm/dd/yyyy on U.S. government forms, the layer declares the pattern:

```json
"format": { "date": { "pattern": "MM/DD/YYYY" } }
```

Every date field then prints `06/05/2021` in place of the formatter's `Jun 5, 2021`, whatever the locale. The patterns are `MM/DD/YYYY`, `DD/MM/YYYY`, and `YYYY-MM-DD`. Extraction reads the text back by the same pattern, so `05/06/2021` on a `DD/MM/YYYY` layer is June 5 under any locale.

A `locale` prints names and words in that locale in place of the formatter's:

```json
"format": { "locale": "en-US" }
```

One binding can print differently from its layer. A binding value can be an object whose `format` merges over the layer's, per property:

```json
"format": { "date": { "pattern": "MM/DD/YYYY" } },
"bindings": {
  "signedOn": "fields.signedOn",
  "filedOn": { "path": "fields.filedOn", "format": { "date": { "pattern": "YYYY-MM-DD" } } }
}
```

For two dates of June 5, 2021, `signedOn` prints `06/05/2021` and `filedOn` prints `2021-06-05`. A binding on an option test, such as `fields.status:married`, or on a split part, such as `fields.ssn:2`, takes no `format`.

A layer that sets only `money.currencyDisplay` and `date.pattern`, with no binding formats, formats all data once before filling, so an invalid value anywhere fails the render. Once the layer sets any other option, a binding sets a `format`, or the layer reads a field that has a `mask`, each value is formatted when a binding, an overlay, or a field-id fill reads it, and only a value that is read can fail the render.

An address in a country with no address layout prints in the generic layout (`line1, line2, locality, region, postalCode, country`) on every layer, in place of failing the render. A layout the formatter supplies for that country through `countryLayouts` comes first. An invalid address is still refused.

Filling a template that carries an XFA form beside its AcroForm, as many government forms do, removes the XFA form and the catalog's `NeedsRendering` entry from the output. A viewer that reads XFA would otherwise show the XFA form's own data in place of the filled fields. That output is written whole, not as an incremental update, so no XFA bytes and no earlier revision stay in the file. A template without XFA is still filled as an incremental update.

Formatting applies to indexed fields, computed values, parties, and field overlays. Invalid values and unknown binding sources reject with field diagnostics. Checkboxes and selection controls retain their raw value identity.

Text outside Latin-1 needs a font that covers it; see [Fonts](#fonts). Without one, filling fails naming the field and the character.

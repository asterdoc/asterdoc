In this guide, we'll use Asterdoc to fill out an IRS W-9 form. The W-9 is a common tax document that businesses use to collect taxpayer identification information from contractors and vendors. It's a great example because it has text fields, checkboxes, and split fields (like SSN broken into three boxes) — all patterns you'll encounter when working with PDF forms.

**About AcroForm Fields**

AcroForm is the original interactive PDF forms technology introduced by Adobe. When a PDF lets you type into text fields, check boxes, or select dropdowns, those elements are AcroForm fields. Each field has an internal (often non-semantic, like `Page1.f1_01[0].top`) name, which Asterdoc uses to map your data to the correct field in the PDF.

<Step>
## Inspect PDF Fields

Before creating bindings, discover the AcroForm field names in your PDF template using `inspectAcroFormFields`.

```ts
import { inspectAcroFormFields } from '@asterdoc/render/pdf'
import { readFileSync } from 'node:fs'

const template = readFileSync('layers/w9.pdf')
const fields = await inspectAcroFormFields(new Uint8Array(template))

console.log(JSON.stringify(fields, null, 2))
// [
//   { "name": "topmostSubform[0].Page1[0].f1_01[0]", "type": "text" },
//   { "name": "topmostSubform[0].Page1[0].f1_02[0]", "type": "text" },
//   { "name": "topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[0]", "type": "checkbox" },
//   ...
// ]
```

This reveals the internal field names that you'll map to your form fields.
</Step>

<Step>
## Define the Form

Create a form with a PDF file layer. The `bindings` object maps PDF field names to your form field expressions.

The `pdf` layer is file-backed, so bind a resolver when you construct the
form — it reads `layers/w9.pdf`, and every instance you derive from `w9Form`
later carries the same resolver.

```ts
import { a } from '@asterdoc/sdk'
import { createFsResolver } from '@asterdoc/resolvers/fs'

const resolver = createFsResolver({ root: '.' })

const w9Form = a.form({
  name: 'w9-tax-form',
  fields: {
    name: { type: 'text', label: 'Name', required: true },
    businessName: { type: 'text', label: 'Business Name' },
    taxClassification: {
      type: 'enum',
      label: 'Tax Classification',
      enum: [{ value: 'individual' }, { value: 'c_corp' }, { value: 's_corp' }, { value: 'partnership' }, { value: 'llc' }],
      required: true,
    },
    llcTaxCode: { type: 'text', label: 'LLC Tax Code' },
    address: { type: 'address', label: 'Address', required: true },
    ssn: { type: 'text', label: 'SSN' },
    ein: { type: 'text', label: 'EIN' },
  },
  defaultLayer: 'pdf',
  layers: {
    pdf: {
      kind: 'file',
      mimeType: 'application/pdf',
      path: 'layers/w9.pdf',
      bindings: {
        // Simple field binding
        'topmostSubform[0].Page1[0].f1_01[0]': 'name',
        'topmostSubform[0].Page1[0].f1_02[0]': 'businessName',

        // Checkbox bindings for enum values
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[0]': 'taxClassification:individual',
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[1]': 'taxClassification:c_corp',
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[2]': 'taxClassification:s_corp',
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[3]': 'taxClassification:partnership',
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].c1_1[5]': 'taxClassification:llc',
        'topmostSubform[0].Page1[0].Boxes3a-b_ReadOrder[0].f1_03[0]': 'llcTaxCode',

        // Nested path for complex types
        'topmostSubform[0].Page1[0].Address_ReadOrder[0].f1_07[0]': 'address.line1',

        // Several values in one field (a template)
        'topmostSubform[0].Page1[0].Address_ReadOrder[0].f1_08[0]': {
          template: '{{fields.address.locality}}, {{fields.address.region}} {{fields.address.postalCode}}',
        },

        // Split fields (SSN split across 3 inputs)
        'topmostSubform[0].Page1[0].f1_11[0]': 'ssn:1',
        'topmostSubform[0].Page1[0].f1_12[0]': 'ssn:2',
        'topmostSubform[0].Page1[0].f1_13[0]': 'ssn:3',

        // Split fields (EIN split across 2 inputs)
        'topmostSubform[0].Page1[0].f1_14[0]': 'ein:1',
        'topmostSubform[0].Page1[0].f1_15[0]': 'ein:2',
      },
    },
  },
}, { resolver })
```

A binding writes a choice into a text box as the option's value, not its label. Give an enum the values the paper form asks for, such as `C`, `S`, and `P` for the LLC code box, and keep the labels for people reading them.
</Step>

<Step>
## Fill the Form

Create a runtime instance by filling the form with data.

```ts
const filled = w9Form.fill({
  fields: {
    name: 'John Smith',
    taxClassification: 'individual',
    address: {
      line1: '123 Main Street',
      locality: 'San Francisco',
      region: 'CA',
      postalCode: '94105',
      country: 'US',
    },
    ssn: '123-45-6789',
  },
})

if (!filled.isValid()) {
  console.log('Errors:', filled.validate().errors)
}
```
</Step>

<Step>
## Render to PDF

Render the filled form. `createLayerRenderer()` selects the PDF implementation from the
layer's MIME type, and the resolver bound to `w9Form` loads the template from
the filesystem — `filled` carries it too, so the render call doesn't repeat it.

```ts
import { createLayerRenderer } from '@asterdoc/render'
import { writeFileSync } from 'node:fs'

const output = await filled.render({
  renderer: createLayerRenderer(),
  layer: 'pdf',
})

writeFileSync('output/w9-filled.pdf', output)
```

The output is a `Uint8Array` containing the filled PDF document with all AcroForm fields populated.
Each value follows its field's own settings: font size, alignment, comb boxes, and multiline
wrapping. The SSN parts land one digit per box. A value too long for its field fails with
`PdfFieldFillError`, naming the field, rather than being clipped. See
[Field appearance](/sdk/renderers/pdf#field-appearance).

`asterdoc validate` finds these failures before any data is filled. It lays out
a typical value at each bound field's length limit, so give every bound text
field a `maxLength` (or a `pattern`) that its box can hold. See
[Checking bindings before filling](/sdk/renderers/pdf#checking-bindings-before-filling).

Latin-1 values fill in Helvetica with no font configuration. To fill names in
Latin Extended, Greek, Cyrillic, or CJK scripts, declare a TrueType font on the
PDF layer. The bound resolver reads it beside the PDF, and it is embedded in the
output:

```ts
pdf: {
  kind: 'file',
  mimeType: 'application/pdf',
  path: 'w9.pdf',
  font: { path: 'fonts/NotoSans-Regular.ttf' },
  bindings: { /* ... */ },
}
```

A value with a character that no font of the layer can draw stops the render.
The error names the PDF field, the artifact value it prints, and the character:

```text
Cannot fill PDF field "form1[0].Page1[0].NativeName[0]" with fields.nameInNativeAlphabet: no available font can draw "王" (U+738B). Declare a font that has this character on the PDF layer of the artifact: "font": { "path": "<file>.ttf" }. The SDK can also take a font for one render: pdfRenderer({ font }).
```

To correct it, declare a font on the layer that has the character, as shown
above. The `asterdoc render` command uses the fonts of the layer only. A host
application that uses the SDK can also pass a font at render time.

`asterdoc validate` finds this before the first render. It prints the values
of each test in the artifact's `tests` with the fonts of each PDF layer, and
reports each value that they cannot draw. The error names the layer, the test,
the PDF field and the artifact path. So when a form takes names in other
scripts, give it a test with such a name.

Scripts that need shaping, such as Arabic or Devanagari, are refused whatever
the font; render those documents from a [React composition layer](/guides/react-layers). See
[Fonts](/sdk/renderers/pdf#fonts) for the full font order.
</Step>

<Step>
## Read a Filled PDF Back

The same bindings work in reverse. Given a completed W-9, `extract` returns the form data and a report for each field:

```ts
import { readFileSync } from 'node:fs'

const { data, report } = await w9Form.extract(readFileSync('output/w9-filled.pdf'))
const fillResult = w9Form.safeFill(data)
if (!fillResult.success) throw fillResult.error
const draft = fillResult.data
```

The city, state, and ZIP code box holds a template, and `Boston, MA 02110` splits into those three values in only one way, so the report marks them `recovered`. See [Several values in one field](#several-values-in-one-field) for when a template reads back, and [Extracting data from a filled PDF](/sdk/artifacts/form#extracting-data-from-a-filled-pdf).
</Step>
</Steps>

## Several values in one field

A string binding is one path. When a PDF box holds several values, write a **template**: a binding object with `template` in place of `path`. It uses the same language as a text layer, so `{{ }}` placeholders take any expression and format modifier, and `{{#if}}`, `{{#unless}}`, `{{else}}` and `{{! comment }}` work as they do there.

```json
"bindings": {
  "topmostSubform[0].Page1[0].Address_ReadOrder[0].f1_08[0]": {
    "template": "{{fields.address.locality}}, {{fields.address.region}} {{fields.address.postalCode}}"
  }
}
```

With a city of Boston, a state of MA and a ZIP of 02110, the box prints `Boston, MA 02110`. Paths start from the expression roots: `fields.`, `parties.buyer.name`, a computed value by its name (`{{total}}`), and a list row by its index (`{{fields.lines[0].amount}}`).

Each placeholder prints its value as a path binding to the same path would. A choice prints its option value, masks apply, the layer `format` applies, then the binding's `format`, then the placeholder's own modifiers. A binding takes `path` or `template`, never both, and a template takes no `part`. Write it on the placeholder instead: `{{fields.dob | part="year"}}`.

### An optional piece

Put a piece that may be missing in a block, so its text goes with it. This street line adds the unit only when there is one:

```json
{ "template": "{{fields.address.line1}}{{#if fields.address.line2 != null}}, {{fields.address.line2}}{{/if}}" }
```

### Line breaks

A line break in the template starts a new line in a multi-line field. In a single-line field the PDF prints it as a space, so `asterdoc validate` reports an error. `asterdoc inspect` shows which text fields are multi-line. A template bound to a field that is not a text field is also an error.

### An empty field

When every placeholder the template reached prints nothing, the field stays empty. With a city and a state that are both empty, `{{fields.city}}, {{fields.state}}` leaves the box blank instead of printing `, `. A branch that holds only literal text prints that text.

### Case

`case: "upper"` in the binding's `format` changes the whole field, the template's own text included. A layer's `case` changes the values only.

### What a template refuses

- `{{#each}}`. A PDF field prints a fixed text, so bind each list row to its own field, such as `fields.lines[0].amount`.
- Signing directives such as `signature(...)` and `initials(...)`. A PDF layer places signing marks through its signature slots.
- A comma-joined path such as `"city, state, zip"`. Write a template instead: `{"template":"{{fields.city}}, {{fields.state}}"}`. A file on an earlier schema version still loads: the upgrade step turns each joined binding into a template that prints the same text, and [`asterdoc migrate`](/cli/commands/migrate) rewrites the file.

`validate()` checks every expression and modifier in a template against the form, as it does for a text layer. The fit check measures each text a template can print, one for each combination of its `{{#if}}` blocks. A template with a computed placeholder is not measured.

### Reading a template field back

`extract` recovers the values only when the field's text splits into the template's values in exactly one way. `Boston, MA 02110` does, with the city line above. `2150 Market Street, Suite 300` with the optional-unit template splits two ways, a street with a unit or a street that holds a comma, so the paths are `not_recoverable` and `extract` does not guess. Text that does not match the template is `unparseable`, and a template that prints a computed value is `not_recoverable`. See [Extracting data from a filled PDF](/sdk/artifacts/form#extracting-data-from-a-filled-pdf).

You've now created a form that fills an existing PDF template using field bindings. The binding syntax handles common patterns like checkboxes for enum values, split fields for formatted data like SSN/EIN, and templates for several values in one box.
